1. **Local Debug Keystore SHA-1** (for local development & simulator testing):
   `B0:32:09:38:E7:52:67:6F:49:BE:B9:CE:99:7C:77:49:A8:F0:A4:25`
2. **EAS Build Keystore SHA-1** (for APK & AAB builds generated by EAS):
   Can be viewed anytime in your Expo Dashboard under **Project -> Credentials -> Android Keystore**, or by running:
   `npx eas-cli credentials -p android`
3. **Google Play App Signing SHA-1** (for published store builds):
   Available in Google Play Console under **Release -> Setup -> App Integrity / App Signing**.

> [!IMPORTANT]
> Under **API restrictions**, check **Restrict key** and enable ONLY:
> * **Maps SDK for Android**
> * **Maps SDK for iOS**
> * **Places API** (if used for autocomplete)
> This prevents external actors from extracting the key from client bundles to run billable web requests.

## 8. AI & Cloud Edge Function Secrets (Strict Token Guardrails)

| Function | Required Secret | Purpose | Token Status |
| :--- | :--- | :--- | :--- |
| `verify-id` | `OPENAI_API_KEY` (Supabase Secret) | One-time identity verification & human presence check | **ACTIVE**: Strictly authorized paid AI use-case |
| `parse-plan-text` | None (Feature flag disabled) | Smart auto-fill for plan creation text | **DISABLED**: Zero token burn. Hardcoded to deterministic local regex parser |
| `send-push-notification` | `SUPABASE_SERVICE_ROLE_KEY` | Relays in-app notifications to Expo Push API | Internal logic (Zero AI tokens) |
| `notify-host` | `SUPABASE_SERVICE_ROLE_KEY` | Dispatches instant join request push notifications | Internal logic (Zero AI tokens) |

### Strict Token Guardrails & Optimization Standards:
1. **Explicit Founder Permission**: The AI agent must NEVER invoke or trigger live OpenAI APIs without direct Founder permission.
2. **Single Authorized Use-Case**: Paid tokens are ONLY authorized for `verify-id`. No tokens may be spent on recommendations, plan parsing, or notifications.
3. **Low-Detail Images**: `gpt-4o-mini` with `detail: "low"` strictly enforces a flat 85 tokens per image (170 tokens total).
4. **Output Token Cap**: Hard-capped at `max_tokens: 150` in `verify-id` to prevent runaway spending.
5. **Client-Side Compression**: Captured photos are compressed at `quality: 0.65` before base64 encoding (sub-300KB payload).
6. **Zero Cloud Storage**: Photos are analyzed in-memory and immediately discarded. Never stored on disk or databases.
